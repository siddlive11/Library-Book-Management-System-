    One scan. The whole transaction.

    From the first card tap to the live database update, a loan takes five steps and a few seconds.

    1

    The student scans their card

    The reader at the desk identifies the student by card ID and pulls up their profile and borrowing history.

    2

    The book's tag is read

    Staff or a self-service station scans the tag on the spine and gets back the title, category and whether it is available.

    3

    The system checks the records

    The ESP32 passes the scan to the application, which confirms the student can borrow and the book is on the shelf.

    4

    The loan is recorded

    A loan is created with issue and due dates, linked to both student and book. The desk display confirms it.

    5

    Availability updates instantly

    The book shows as issued everywhere at once. At the exit gate, a book without a loan sets off the buzzer.

    Built for precision.

    Hardware and software chosen to do one job well: know where every book is.

    RFID system

    13.56 MHz readers and passive tags give every book and student card a unique identity.

    ESP32 and Arduino

    The microcontroller reads each scan, drives the desk display and talks to the server.

    MySQL database

    Books, students, loans and history stored with integrity constraints.

    Java and Spring Boot

    A REST backend handles loan validation, fine calculation and the API.

    Web interface

    HTML, CSS and JavaScript for admin work, search and live status.

    Buzzer alert

    Sounds when the gate reader detects a book that was never issued.
